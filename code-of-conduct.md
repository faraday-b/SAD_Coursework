# Code of Conduct

This document defines the code of conduct for the project.

## 1. Communication and Collaboration

All official project communication will take place on WhatsApp and GitHub.

Team members agree to respond to urgent queries within 24 hours of the week.

Regular scrum meetings will be held to discuss progress, decisions, and roadblocks.

## 2. Version Control and Development

No code shall be pushed directly to the main branch; correct feature branches must be created and used for all tasks.

Team members must commit code regularly to show collective contribution and coordination.

All code must be clean, organized and effectively commented.

Ensure the application builds without errors in IntelliJ before pushing to the shared repository.

## 3. Task Allocation and Responsibility

Tasks will be allocated fairly across team members based on the project scope.

Each member is responsible for their assigned tasks to ensure their individual contribution grade is protected.

Internal milestones will be set 48 hours before the official Sprint deadlines to allow for integration and review.

## 4. Code Review and Attendance

All members must be ready for the graded code review sessions with the application building in IntelliJ.

Attendance at the scheduled lab sessions for code reviews is mandatory.

Members must arrive on time to avoid the grade being capped at 40%.

## 5. Conflict Resolution

Constructive Feedback: Peer reviews and feedback must be handled professionally and non-personally.

Disagreement: If the team cannot reach a consensus, a majority vote will be taken, or the module tutor will be consulted for mediation.

## Agreement

By contributing to the GitHub repository, all team members acknowledge they have read, understood, and agreed to this Code of Conduct.
